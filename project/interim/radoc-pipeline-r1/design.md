# Canonical .radoc for reading and audio

## Convert to one document model at intake

Treat .radoc as the shared document contract. Import EPUB, PDF, DOCX, HTML, RTF, Markdown and text through format adapters, then hand the same typed, immutable ranges to display, language analysis, casting, planning, playback and export. Open a saved .radoc through a reader adapter that yields those same ranges. In memory, pass typed ranges directly through the existing worker handoff. Persist them in the working book as they are admitted. A fresh range can be used without writing a complete archive and reopening it for the next stage.

```text
Source file, shared text or paste ──→ format adapter ──┐
Existing .radoc ───────────────────→ versioned reader ┼→ canonical prepared .radoc ranges
Reusable source checkpoint ────────→ validated reader ┘       ├→ display and navigation
                                                              └→ analysis and render planning
                                                                        ↓
                                                   verified saved audio or on-demand synthesis
                                                                        ↓
                                                      sample-frame placement → playback/export
```

The baseline is already close. The import supervisor publishes contiguous prepared ranges and checkpoints them under a source revision. Legacy v1–v4 .radoc stores document data. V5 is an indexed audio-book ZIP containing prepared ranges, optional analysis, and WAV scene assets. The v5 reader validates the index and first requested range, then materializes members on demand. Existing verified audio can play with model initialization deferred. Missing audio can be rendered selectively. The simplification is to unify these consumers behind one canonical range contract, with each current reader/writer adapting to it. [Current document pipeline](../../architecture/document-speech-pipeline.md#s6-portable-audio-books), [checkpoint reader](../../../lib/src/services/reader_document_repository.dart), [v5 package](../../../lib/src/services/radoc_audio_package.dart)

Whole-document conversion can be an explicit offline ingest or portable publication operation. Interactive Open starts when the requested prepared range and sufficient verified audio are ready. Parsing to EOF, finishing neural analysis, rendering the whole book, and publishing a complete archive each have independent coverage and completion. An EOF-complete text graph can have partial analysis and no audio. An interrupted conversion can retain its verified ranges without claiming a complete book. Any reuse of an interrupted prefix must validate its exact source revision and dependencies. This is proposed work beyond the current complete-checkpoint reuse path. [Product definition](../../product-definition.md)

### Canonical data and downstream ownership

| Layer | Data and responsibility |
| --- | --- |
| Prepared content | Original/source revision, stable content anchors, normalized spoken and display ranges, source mapping, authored direction and known coverage. Container details stop at the intake adapter. |
| Analysis and casting | Versioned evidence and linguistic boundary candidates linked to canonical spans, provider/model provenance and uncertainty. Reconcile across windows, protect explicit user choices and keep them independent of acoustics. |
| Rendition | Effective voice and model bindings, engine-ready request, cut decisions, asset references, exact frame counts and resolved timing where known. Reuse only compatible captured renders. |
| Audio assets | Encoded payload, format, decoded sample format, integrity and sample count. Read only as needed. Files and packets are delivery/storage units. |

During progressive preparation, the existing document owner admits demand, bounds lookahead by range credit and validates source revision and generation before publishing. Analysis can refine future uncommitted work. Captured speech and explicit directions keep their original provenance. A seek prioritizes the requested range. A changed source or cancelled generation cannot admit stale decode, analysis, plan or audio results. Keep acquisition, parsing and disk work off the Flutter UI isolate. Publish final archives atomically after verifying coverage. [Preparation owner](../../../lib/src/services/document_preparation_supervisor.dart), [range cache](../../../lib/src/services/reader_document_repository.dart)

## Use ModernBookNLP evidence for linguistic cuts

Today the Dart importer recovers structure, heuristically splits sentences and mixed quotation/narration, and maps each speech fragment to the source. Base inference takes punctuation and block structure as boundary hints. It treats uppercase runs and exclamations as emphasis candidates and records rule-based pronunciation or say-as candidates. The speaker heuristic looks at explicit reporting tags, nearby context, pronouns, action cues and recent turn patterns. It can retain an unknown speaker. These rules provide fast provisional input without waiting for the neural provider. [Importer segmentation](../../../lib/src/services/document_import_service.dart#L2186), [annotation inference](../../../lib/src/services/base_speech_annotation_inference_service.dart#L20), [speaker rules](../../../lib/src/services/speaker_attribution_service.dart#L214)

ModernBookNLP already emits token ranges, sentence and paragraph IDs, POS and dependency heads, plus quote spans, speakers, entities and coreference. The current worker persists its tokens, entities, quotes and book artifacts. Its production adapter maps compatible quotes to already prepared dialogue spans. A mismatch remains unresolved. The current Dart chunk planner still chooses render spans from the prepared segments using size targets, route and performance boundaries, and engine-specific scene packing. The reviewed [R22 decision](https://github.com/kellyjanderson/readaloud/issues/110#issuecomment-6671953753) and [S2 scope](https://github.com/kellyjanderson/readaloud/issues/127#issuecomment-6673916468) establish evidence reuse and refinement with existing turn boundaries. They do not establish that linguistic or synthesis cut ownership moved in the integrated source. [Linguistic record extraction](../../../assets/modernbooknlp_worker.py#L80), [turn binding](../../../lib/src/services/modernbooknlp_character_adapter.dart#L27), [chunk planner](../../../lib/src/services/chunk_planner_service.dart#L32)

The planning direction is to project qualified ModernBookNLP evidence into the canonical range and let it drive linguistic cut candidates. Use sentence, clause and quotation evidence that maps exactly to source anchors. Preserve source-format structure, authored directions and manual corrections. Prefer already valid saved analysis. Use provisional cuts for a first listen when analysis is absent or waiting. Compare matched bounded windows against current Dart cuts on the same text. Retire equivalent deep rules after qualification. Both producers feed one schema and one cut-decision owner.

ModernBookNLP's syntax and quotes are useful input for phrasing and who speaks. The pinned outputs do not prescribe emphasis, phonemes, delivery speed, pause durations, pitch contours or emitted audio alignment. A language boundary is a candidate place to render. The synthesis planner still decides how much context a model needs, where voice/delivery changes require a cut, and how to stay within resource limits. Never apply provider token offsets as audio times. [Upstream outputs](https://github.com/booknlp/booknlp#output), [Read Aloud capability assessment](../../research/modernbooknlp-capability-reuse.md)

## Place audio by timing rather than file boundaries

Today the WAV policy measures quiet PCM and can trim the start or a later join. Its 60/120/240/420/650 ms class thresholds govern how much leading silence may be removed when the previous tail is already known. They do not insert a pause. The native Fish streaming path already identifies a packet by frame position within its parent render. It does not infer word positions per packet. The proposed change is to make explicit render timing authoritative for all placement. [WAV join policy](../../../lib/src/services/synthesis_boundary_policy.dart#L341), [packet contract](../../../lib/src/services/speech_audio_packet.dart#L1)

Use a content anchor and render identity to resolve each piece to an exact half-open sample-frame interval in its rendition. Record source-frame start/count, rate and channel format, destination placement, and timing provenance. Clip-local positions plus a bounded composition index avoid rewriting every later timing record when an earlier span changes duration. Preserve native storage rates. If adjacent assets have different rates or the device needs another rate, convert at the render boundary with an explicit, consistent mapping and qualify drift. Maintain separate authored timing intent, realized source-to-audio alignment and presentation time at the user's playback rate. Reuse the [R19 timing contract](https://github.com/kellyjanderson/readaloud/issues/110#issuecomment-6670899379) and evaluate the [R20 C ABI/Dart FFI scaffold](https://github.com/kellyjanderson/readaloud/issues/110#issuecomment-6671095679) for interval rules. The scaffold currently supplies interval math, with no player, mixer or reliable alignment.

- **Storage or transport split inside one render.** Append adjacent frames exactly. The second interval begins at the first interval's end, even when the cut is mid-word. The split adds zero frames and needs no crossfade. Encoded assets are decoded into PCM for placement. Copying encoded files or concatenating WAV headers would not implement this.
- **Independent synthesis split.** A file join can be seamless yet two generations can disagree in phonemes, breath, pitch, pace or room tone. Avoid independent synthesis cuts inside a word. For a forced boundary, prefer model-supported continuation or re-rendering a small span with shared context. Use overlap or crossfade only for valid compatible material with measured alignment and explicit gain/trim rules. A mix of mismatched words can double or obscure them.
- **Linguistic pause.** Text structure, punctuation, authored directions and supported prosody determine intended phrasing. Preserve the pause the model already rendered. If a verified timing plan requires a pause of a specific duration, account for that realized pause once, wherever it spans the split. Trim surplus only with reliable boundary evidence. Unknown placement stays unresolved, triggers conservative playback or a re-render, and does not imply a gap duration.
- **Unready next piece.** Hold/rebuffer truthfully, retain the exact continuation position and record starvation. A runtime stall has no place in the saved audio timeline.

One continuous output can be fed from a bounded PCM ring, scheduled contiguous buffers or a qualified native player/mixer. Scheduling belongs to the audio renderer and device clock. The planner gives timing and provenance with opaque asset references. It has no obligation to open media files or choose a codec. Simultaneous buffers require explicit overlap/mix timing. Ordinary adjacent speech needs back-to-back placement. Synthesis carries source and session identity into audio completion, and the compositor rejects any obsolete frame placement before it enters the device queue.

## Store durable audio losslessly

Take decoded native-rate PCM and its frame map as the common media boundary. Encode finalized assets losslessly. Compare **FLAC first** for portable .radoc audio, **ALAC in an explicit standard container** where the platform path qualifies, and **NARALAC** for standalone files that benefit from its indexed metadata. The canonical .radoc manifest already has timing/provenance around audio assets. It should carry mandatory book-relative timing and media references regardless of codec. NARALAC's skippable `META` is useful for optional Read Aloud descriptors that travel with a file. Its recorder-clock metadata needs a defined profile before synthetic speech can claim compatibility. Current v5 declares and validates WAV, so another container requires an explicit compatible reader/version strategy. Preserve existing v1–v5 read paths and saved PCM. [Lossless container comparison](../../research/radoc-lossless-audio.md), [current v5 scene schema](../../../lib/src/models/radoc_audio_manifest.dart#L68)

Follow the [Flutter/Dart platform directive](../../../AGENTS.md#flutterdart-platform-and-native-bindings). Model, codec and output adapters present typed Dart APIs with platform-specific implementations and capability reports. The app controls content, timing and rendition identity through portable contracts. Native backends own their execution, file/PCM I/O and platform setup.
